# Contributing to ESP32 Firmware

Thank you for your interest in contributing to this project! This document provides guidelines and instructions for contributing.

## Code of Conduct

Please be respectful and constructive in all interactions.

## Getting Started

1. **Fork** the repository
2. **Clone** your fork: `git clone https://github.com/your-username/firmware-esp32.git`
3. **Create** a feature branch: `git checkout -b feature/your-feature-name`
4. **Make** your changes
5. **Commit** with clear messages: `git commit -m "Add feature description"`
6. **Push** to your fork: `git push origin feature/your-feature-name`
7. **Create** a Pull Request

## Development Guidelines

### Code Style

- Follow the existing code style in the repository
- Use meaningful variable and function names
- Keep functions small and focused
- Add comments for complex logic

### Commit Messages

Use clear, descriptive commit messages:
```
Add description of changes

- Bullet point 1
- Bullet point 2

Closes #123
```

### Testing

- Write unit tests for new features
- Ensure all tests pass before submitting PR
- Test on actual hardware when possible

### Documentation

- Update README.md for significant changes
- Add inline comments for complex code
- Update API documentation if applicable

## Pull Request Process

1. Update documentation as needed
2. Add tests for new functionality
3. Ensure all CI checks pass
4. Keep PRs focused on a single feature or fix
5. Provide clear description of changes

## Reporting Issues

When reporting bugs, please include:
- ESP32 board model and revision
- Environment (IDE, framework version, toolchain)
- Reproduction steps
- Expected vs. actual behavior
- Relevant code snippets or logs

## Questions?

Feel free to open an issue or discussion for questions about the project.

Thank you for contributing!
